# 01 ｜ プロジェクト全体像

## 背景

株式会社FORTでは、日々の業務が複数のGoogleスプレッドシートに分散している。

- 日報（社員ごとのシートに午前／午後／夜の予定と実績）
- 勤怠・休日表（月ごとのシートに出勤・休みを記録）
- 完成見学会の予約表（会場ごと・日ごとの来場予約枠）
- 席／来場カウンターの予約
- 案件の進捗管理
- そのほか、資格管理・各種申請・社内資料など

これらは「その場では回る」が、次のような課題がある。

- 情報がバラバラで、全体像がひと目で分からない。
- 誰がいつ何をしているか、休みか、を横断的に見られない。
- スプレッドシートは同時編集や権限管理に限界がある。
- スマホから使いにくい。
- 経営が「会社の現在地」を把握するのに手間がかかる。

## このプロジェクトのゴール

**FORTの業務を一つにまとめた社内ポータルサイトをつくる。**

社員が毎朝ログインすれば、自分のやること・休みの人・予約状況・案件の進捗が
ひと目で分かる。経営は会社全体の状況をダッシュボードで俯瞰できる。
データはすべてデータベースに保存され、スマホでもPCでも使える。

### 目指す状態

- 社員は「今日やること」「自分の勤怠」「日報の提出」をポータル上で完結できる。
- 総務は勤怠・休日・申請の管理をポータル上で行える。
- 営業は見学会・来場の予約状況を確認・登録できる。
- 経営は全社ダッシュボードで稼働・案件・遅延・負荷を把握できる。
- すべての情報が一箇所に集約され、スプレッドシートを行き来しなくてよい。

## スコープの考え方

「思いつく限り全部」載せたい、という要望に対しては：

- **構想は全部描く**（`02_features.md` にフルスコープの機能一覧）。
- **実装は段階的に**（`06_roadmap.md` のPhase順）。

こうすることで、全体像を見失わずに、着実に動くものを積み上げられる。

## 開発の担い手

このシステムは **Claude Code** を使って開発する。
そのため、本ドキュメント群は「人間が読む仕様書」であると同時に
「Claude Codeが読んで実装できる指示書」として書かれている。

## 非ゴール（今回やらないこと）

- 会計・給与計算そのもの（既存の会計システムと役割分担する）。
- 顧客向けの外部公開サイト（これは社内ポータル）。
- スプレッドシートの完全な廃止（移行は段階的に。当面は並行運用も可）。
