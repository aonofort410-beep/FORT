# FORT STANDARD デザインシステム

FORT標準仕様Webガイド（TOP／性能／外装／内装／キッチン／浴室／洗面／トイレ／収納／照明／施工事例／保証）のためのビジュアルルール。

**参照する世界観**：Apple／Aesop／MUJI／NOT A HOTEL
**避けるべき世界観**：住宅会社にありがちな「情報量で押す」デザイン（原色バッジ、詰め込みグリッド、乱立するCTA、作り笑いのストックフォト）

**根底のルール（全項目共通の判断基準）**：
> 静けさは「足すこと」ではなく「引くこと」でつくる。色・装飾・動きを足して上質さを演出しない。要素を削り、余白と一つひとつの精度で語らせる。

既存の `fort-series-lp.html`（3シリーズ紹介LP）はセールス訴求を目的とした華やかなトーンで問題ないが、本ガイドは「信頼を静かに積み上げる」ことが目的のため、意図的にトーンを引き算する。色数・ボタン種類・ラベル演出は既存LPより明確に少なくする。

---

## 1. カラーパレット

**原則：ベースはほぼ無彩色、アクセントは1色のみ。使う場所を限定する。**

| トークン | 値 | 用途 |
|---|---|---|
| `--std-bg` | `#F7F5F0` | ページ基本背景（純白ではなく、紙のような温かみのあるオフホワイト） |
| `--std-bg-deep` | `#16130F` | ごく限られたセクション（保証・最終CTAなど）のみに使う深色背景 |
| `--std-ink` | `#1E1B17` | 本文・見出しの基本文字色（純黒は使わない） |
| `--std-ink-soft` | `#6E675D` | 補足文・キャプションなど、主張を抑えたい文字 |
| `--std-line` | `#E6E1D6` | 区切り線・ヘアライン（枠線ではなく「境界の気配」として使う） |
| `--std-accent` | `#93805F` | サイト全体で唯一のアクセント色。リンク・下線・プライマリボタンにのみ使用 |
| `--std-white` | `#FFFFFF` | 深色背景の上の文字・アイコンなど、コントラスト確保が必要な箇所限定 |

- アクセントカラーは **常にこの1色のみ**。ゴールド系を薄める／濃くするなどの微調整はしても、色相を増やさない。
- 状態色（エラー・成功など）は本サイトの性質上ほぼ不要。フォーム等でやむを得ず必要な場合も彩度を極力落とす。
- 「1画面に使う色は最大3種（背景・文字・アクセント）」を上限にする。

---

## 2. 文字サイズ

**原則：書体は2種まで。サイズ段階は少なく、余白と行間で階層をつくる。**

- 見出し書体：明朝体（Noto Serif JP 相当）／本文書体：ゴシック体（Noto Sans JP 相当）。装飾書体は追加しない。
- ウェイトは Regular(400) と Medium(500) の2段階のみ。Bold(700)以上は基本的に使わない（強調は色・余白・サイズで行い、太字に頼らない）。

| 用途 | サイズ（目安・レスポンシブ） | 行間 | 備考 |
|---|---|---|---|
| Display（TOPヒーロー） | `clamp(2.2rem, 5vw, 3.4rem)` | 1.55 | サイト内で1〜2箇所のみ使用 |
| H1（ページタイトル） | `clamp(1.8rem, 4vw, 2.4rem)` | 1.5 | 各ページ1回 |
| H2（セクション見出し） | `clamp(1.4rem, 3vw, 1.9rem)` | 1.5 | |
| H3（項目名） | `1.125rem〜1.25rem` | 1.6 | 仕様項目名など |
| Body（本文） | `1rem（16px）` | 1.9〜2.0 | 既存LP同様、行間は広めに保つ |
| Small（注釈・キャプション） | `0.8125rem` | 1.7 | |
| Label（アイキャッチ小見出し） | `0.75rem` letter-spacing `.28em` | – | **1ページにつき最大1回まで**（現行LPのように各セクションに付けない） |

- 本文の最大文字数目安は1行30〜36字（後述の余白ルールと連動）。読みやすさを密度より優先する。

---

## 3. 余白ルール

**原則：8pxグリッド。「詰める」より「空ける」方に必ず倒す。**

- 基本スケール：`8 / 16 / 24 / 32 / 48 / 64 / 96 / 128 / 160 / 200`（px）
- セクション上下パディング：モバイル最小 `96px`、PC `160〜200px`（既存LPの `70〜120px` よりさらに広く取り、"住宅会社の詰め込み感"を明確に排除する）
- コンテンツ最大幅：`1040px`。それ以上の左右は必ず余白として残す（画面いっぱいに文字や要素を広げない）
- 本文テキストブロックの最大幅：`640px` 程度（読みやすさのための行長制限）
- **1スクリーン1メッセージの原則**：1つのセクションに複数の主張・複数のCTA・複数の画像グリッドを同時に詰め込まない
- 関連要素の間隔は小さく（`8〜16px`）、無関係な要素間の間隔は大きく（`64px`以上）。罫線やボックスではなく、余白の大小そのものでグルーピングを表現する

---

## 4. 写真の使い方

**原則：1セクション1枚。写真は「説明」ではなく「余韻」のために置く。**

- サムネイルを敷き詰めたグリッド演出（6〜8枚の写真を並べるような構成）は基本的に使わない。1つの主張につき象徴的な1枚を選ぶ。
- 色調は温かみのある低〜中彩度に統一（不動産サイトにありがちな彩度高め・青白い照明の写真は避ける）。全ページで色温度・トーンを揃える。
- 写真へのテキスト重ねはTOPのヒーローなど最小限の箇所に限定し、通常セクションでは写真とテキストを分離して配置する。
- アイコンバッジ・「NEW」リボン・メーカーロゴの写真上への重ね合わせはしない。
- 「全体を見せる」広角写真より、素材の質感やディテールが伝わる寄りのカットを優先する（引き算の説得力）。
- ストックフォト的な作り笑いの家族写真・書類を持つ営業スタッフ写真などのクリシェは使用しない。実際の施工・素材・空間の写真のみを使う。
- アスペクト比はコンテキストごとに統一する（例：ヒーロー＝超横長、ディテールカット＝4:3、施工事例一覧＝統一比率）。1ページ内で比率を乱立させない。

---

## 5. カードデザイン

**原則：「箱」で囲わない。罫線・余白・タイポグラフィで区切る。**

- 現行LPの `.fsl-ocard`（枠線＋影＋ホバーで持ち上がる＋上部にゴールドバーが伸びる）のような装飾は本ガイドでは採用しない。
- カードは背景色や太い枠線を持たず、上下の余白とヘアライン（`--std-line` 1px）だけで区切る「静かなリスト」として設計する。
- 影（box-shadow）は基本的に使わない。ホバー時の演出も「持ち上げる」ではなく、文字色・下線のわずかな変化に留める。
- 1行に並べるカード数は最大3つまで（PC）。詰め込みグリッドにせず、必要なら縦積みのストーリー形式にする。
- カード内の要素は「番号（任意）／タイトル／一行説明／矢印」程度にとどめ、アイコンやバッジで賑やかにしない。

---

## 6. ボタンデザイン

**原則：ボタンの種類は2つまで。1画面に1アクション。**

- **Primary（唯一の強調ボタン）**：塗りつぶし背景 `--std-accent`、文字は `--std-white`。1ページに1回だけ使う「本当に押してほしい」ボタン（相談する、資料請求する等）。
- **Text link（それ以外すべて）**：下線＋矢印のテキストリンク。背景色を持たない。ページ内の副次的な導線（他ページへ、事例を見る等）はすべてこちらに統一する。
- 現行LPにある `light / ghost / chip` のような複数のボタンバリエーションは作らない。バリエーションが増えるほど「静けさ」が壊れる。
- ホバーは色のわずかな変化または下線のスライドのみ。拡大・バウンス・影の出現などの演出は行わない。
- 1つの画面（ファーストビュー含む）に複数の同格CTAを並べない（「相談する／資料請求／来店予約／LINE登録」を横並びにするような構成はしない）。

---

## 7. スマホ表示ルール

**原則：情報量を減らす。1カラム。横スクロールに頼らない。**

- 常に単一カラム。PC版で並べていた画像＋テキストの2カラムは縦積みにするが、余白は圧縮しない（PCと同等の"間"を保つ）。
- 比較表など横に長いコンテンツは、横スクロールに頼るのではなく、まず「本当に必要か」を疑う。必要な場合も列を絞り込み、シンプルな縦積みリストへの置き換えを優先する。
- タップ領域は44px以上を確保。
- グローバルナビゲーションは最小限の項目のみ（ハンバーガーメニューの中に多階層・大量リンクを詰め込まない）。
- 画面下部などに複数のCTAボタンを常時フロート表示させない。常設が必要な場合も1つに絞り、控えめな見た目にする。

---

## 8. PC表示ルール

**原則：余白を左右に大きく残す。対称グリッドより非対称レイアウト。**

- コンテンツ最大幅 `1040px` を中心に据え、ブラウザ幅が広いほど左右の余白が広がる構成にする（コンテンツを画面幅いっぱいまで引き伸ばさない）。
- 画像とテキストは3〜4列の対称グリッドではなく、既存LPの `.fsl-series__inner` のような非対称2カラム（画像とテキストが交互に反転する構成）を基本形にする。
- ナビゲーションバーは項目数を絞る（電話番号・複数CTA・言語切替などを一度に並べない）。
- フッターに大量のサイトマップリンクやバナー広告を並べない。カテゴリ一覧＋最小限の会社情報＋CTA程度に留める。
- ホバー演出は控えめに統一し、要素ごとに異なる派手な演出を作らない。

---

## 9. アニメーション方針

**原則：動きは「気づかれない」ことを目指す。演出のための演出はしない。**

- スクロールに応じたフェード＋わずかな上方向への移動（既存LPの `data-fsl-reveal` の考え方は踏襲してよい）。ただし速度はやや遅め（600〜900ms）、イージングは `ease-out` 系のみ。
- 同一画面内で同時に動く要素の数を絞る（現行LPのように多数の要素が個別にバラバラ動くと「賑やかさ」が生まれるため、まとまりごとに1つの動きとして扱う）。
- ホバー時の拡大（写真の `scale`）は使うとしても非常に控えめ（1.02程度まで）。バウンド・回転・パルスなどのギミックは使わない。
- オートプレイのカルーセル／スライダーは使わない。
- `prefers-reduced-motion` への対応は必須（既存LPの実装方針を踏襲）。
- パララックスや背景動画のような「効果のための効果」は採用しない。

---

## 10. やってはいけないデザイン

- 各セクションに毎回ゴールドのeyebrowラベル（例：現行LPの `THE FORT SERIES` のような小見出し）を付けること → 1ページにつき最大1回に制限する
- アクセントカラーを2色以上同時に使うこと
- ボタンの種類を3つ以上用意すること（`light / ghost / 通常` のような分岐を増やさない）
- 比較表・バッジ・アイコンを多用して「情報量」で見せようとすること
- 装飾目的の影・太い枠線・グラデーションを重ねること
- ホバー時のバウンス・拡大・回転などのギミック演出
- 隙間なく詰め込んだ3〜4列のカードグリッド
- スマホでの横スクロール前提のUIを増やすこと
- 作り笑いの家族写真、書類を持つ営業スタッフの写真などストックフォト的クリシェの使用
- フッターへの大量のサイトマップリンクやバナー広告の設置
- 同一画面に複数の同格CTAを並べること（1画面1アクションを崩す）
- 全部大文字＋太字の強い主張的コピーの多用
- メーカーロゴを一覧でズラッと並べるパーツを作ること（「標準仕様＝思想」という前提に反するため）

## 補足：既存LPとの関係

`fort-series-lp.html` は購買意欲を高めるセールスLPとして、ある程度の華やかさ（chipボタン・reveal多用・ゴールドラベル多用）を許容して問題ない。一方、本デザインシステムが対象とする「FORT STANDARD」は信頼構築が目的のため、意図的にトーンを引き算している。両者はブランドカラー（ゴールド系アクセント）は共有しつつ、装飾密度は明確に別物として扱う。将来的に両サイトの一貫性を高めたい場合は、既存LPのボタン・カード演出を本デザインシステムの水準に寄せて簡素化することを推奨する（実施は別タスクとして検討）。
